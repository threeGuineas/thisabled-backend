# SAFE 그루밍 평가 설계

## 목적

기존 SAFE 모델의 그루밍 관련 미탐 원인을 단일 발화의 어휘 문제가 아니라 신호 조합과 대화 단계별로 분리해 측정한다. 평가는 모델 서버의 `POST /analyze` 계약을 그대로 사용하며, 백엔드의 채팅 전달 로직은 변경하지 않는다.

## 범위

- 기존 AI 저장소의 `data/synthetic/emergency/3a/test.jsonl` 50건을 기준셋으로 재사용한다.
- 백엔드 작업공간에 별도 평가용 하드케이스를 추가한다. 모든 예시는 탐지 신호 확인을 위한 비노골적 문장으로 제한한다.
- 복합 문장뿐 아니라 단일 신호만 있는 짧은 최소 케이스도 포함해 복합 신호 의존으로 인한 미탐을 분리한다.
- 다음 그루밍 신호 축을 균형 있게 포함한다.
  - 비대칭 친밀감: 처음부터 과도한 특별대우·독점적 신뢰 요구
  - 고립화: 가족·친구·지원 인력과의 소통 차단 유도
  - 의존성: 돌봄·이동·의료·생활 도움을 발신자에게만 의존하게 함
  - 비밀·경계 침범: 비밀 강요, 사적 정보·사진 요구
  - 복합 단계: 위 신호 중 2개 이상이 함께 나타나는 문장
- 정상 반례도 포함한다.
  - 가족·친구의 상호적인 친밀감
  - 활동지원사·치료사 등 역할과 공개적 절차가 명시된 도움
  - 비밀 강요나 독점성이 없는 일반적인 격려
- 각 케이스는 `case_id`, `text`, `expected_risk`, `subcategory`, `receiver_is_minor`, `notes`를 가진다.
- 기본 평가는 그루밍 위험 케이스의 `flagged` Recall과 반례의 `flagged` FPR을 산출한다. 성인·미성년 수신자 결과를 따로 보고한다.

## 실행 흐름

1. 평가기는 JSONL을 읽고 각 케이스를 `POST {base_url}/analyze`로 전송한다.
2. 응답의 계약 필드 `verdict`만 정답 비교에 사용하고, `risk_prob`, `level`, `probs`, `latency_ms`는 진단용으로 보존한다.
3. 케이스별 결과와 전체/하위범주별 집계를 JSON으로 저장한다.
4. 서버가 없거나 응답 형식이 잘못되면 케이스별 오류로 기록하고 종료 코드는 실패로 한다. 누락된 서버 결과를 정상 판정으로 간주하지 않는다.

## 성공 기준

- 합성 케이스가 결정론적으로 생성·검증된다.
- 평가기 단위 테스트가 서버 없이 지표 계산, 하위범주 집계, 잘못된 verdict 처리를 검증한다.
- 실제 서버 평가 결과에서 단계별 Recall/FNR과 반례 FPR을 확인할 수 있다.
- 결과에는 합성 데이터 기반이라는 한계와 단일 메시지 평가라는 한계를 명시한다.

## 비범위

- 모델 가중치, 임계값, 규칙 보조 레이어 수정
- 다중 턴 모델 구현
- AI 저장소의 기존 데이터·코드 수정
- 백엔드 SAFE 채팅 API 동작 변경
