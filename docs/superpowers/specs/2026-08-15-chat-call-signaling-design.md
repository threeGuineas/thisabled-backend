# CHAT-05 음성·영상 통화 시그널링 설계

## 목표와 경계

친구 1:1 채팅방에서 WebRTC 음성·영상 통화를 시작할 수 있게 한다. 백엔드는 통화 권한과 일회성 시그널 전달만 담당하며, 음성·영상 데이터와 SDP/ICE 후보를 DB에 영구 저장하지 않는다. 실제 미디어 연결은 프론트엔드 WebRTC 피어 간에 이루어진다.

## 정책

- `active` 상태의 실제 친구 방만 허용한다.
- 양방향 차단, 어느 방향이든 SAFE 전송 제한, 미성년자–성인 조합은 통화를 거부한다.
- 초대 수신자가 WebSocket 온라인 상태일 때만 통화를 시작한다.
- 사용자당 동시에 한 통화만 허용한다. Redis 원자 연산으로 발신자와 수신자를 함께 예약한다.
- 초대는 60초, 수락 후 통화는 최대 4시간 뒤 자동 만료한다. 종료·거절 시 즉시 제거한다.
- 시그널 데이터는 요청당 JSON 32KiB 이하로 제한하며 Redis에 통화 세션 수명 동안만 보관한다.

## API와 이벤트

- `POST /chat/rooms/{room_id}/calls` — `{kind: audio|video}`로 초대 생성.
- `GET /chat/calls/{call_id}` — 재연결 시 현재 통화 상태 조회.
- `POST /chat/calls/{call_id}/signals` — `offer`, `accept`, `answer`, `ice`, `decline`, `end` 전달.
- 상대방 WebSocket에는 `call.invited` 또는 `call.signal` 이벤트를 보낸다.
- 이벤트에는 통화·방·참여자 식별자와 필요한 시그널만 포함하고 채팅 원문은 포함하지 않는다.

## 오류 계약

- 403: 친구·차단·연령·전송 제한 정책 위반.
- 404: 참여하지 않은 방·통화 또는 만료된 통화. 존재 여부를 구분해 노출하지 않는다.
- 409: 상대 오프라인, 두 사용자 중 하나가 다른 통화 중, 현재 상태에서 허용되지 않는 시그널.
- 413: 시그널 JSON이 32KiB를 초과.

## 검증

- 친구/온라인 정상 초대와 Redis·WebSocket 이벤트.
- 비친구 요청방, 오프라인, 연령 교차, 전송 제한 거부.
- 비참여자 조회·시그널 404.
- 역할별 허용 시그널, 거절·종료 즉시 삭제, 동시 통화 방지, 크기 제한.
