# Q: 영상 자막 부분 계속 오류난다는데 다시 확인해봐

## Answer

Expanded from original query via graph vocab: [caption, upload, video, transcribe, segment, whisper, processing, retry, failed, stt, media, audio, dict]. Runtime logs show Whisper transcription itself returns, but app/services/stt.py transcribe_segments assumes each response segment supports attribute access. With openai 1.30.5 the live response segments are dictionaries, causing AttributeError: dict object has no attribute start on every attempt. All 10 stored video media rows are failed and their posts remain processing. CaptionStatusOut only returns caption_status, so the frontend correctly enters caption-failed but has no error code or reason to display. Fix should normalize both dict and SDK model segment shapes, add a real response-shape regression test, avoid retrying paid transcription for local serialization errors, and expose stable failure_code/failure_message fields.

## Outcome

- Signal: corrected
- Correction: The earlier missing-ffmpeg issue was fixed. The current recurring failure is response-shape incompatibility: dict segments are read with attribute access in stt.py.
